# 计价审查的证据分级

只在核对测试覆盖、CI记录或交付结论时读取。本清单规定证据口径，不指定新的优惠规则。

## 输入与资格

- 对每个入口记录：服务端商品价格、请求/实际分配数量、勾选SKU、购物车来源、账号优惠使用状态、自动任务资格、规则版本。
- 找到资格查询与报价/下单消费资格的真实调用，不用某个参数字段存在替代链路接通证据。
- 同公式、同输入才适合比较金额相等；不同资格导致的合法差异单独说明。
- 金额以分存储、计算和断言，UI显示精度另查；推导出可能显示不同，仍不等同于已复现界面错误。

## 测试与运行

| 证据 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 源码/调用链 | 入口实际引用同一函数，或代码存在特定分支 | 该路径已被运行、事务并发正确 |
| 测试源文件 | 有针对某条件的断言及夹具 | 用例已执行通过 |
| 使用mock的测试执行结果 | 指定模拟条件下的程序行为 | 真实SQL、真实锁竞争、线上模型行为 |
| CI配置文件 | 配置了触发条件、命令和环境 | 任意commit已触发或执行成功 |
| CI日志/截图 | 所展示运行的步骤与统计 | 未展示的commit、后续修改或被跳过的用例已验证 |
| 对应commit的可核对运行记录 | 指定源码版本的执行状态及日志 | 自动补足未执行的真实数据库/浏览器测试 |

检查 `package.json` 的实际脚本、Vitest发现范围、环境开关与跳过条件；分别记录文件数、用例数、passed/failed/skipped，不能相加混用。一个文件包含库存和价格测试时，不把文件总数都计为价格用例。

若报告依赖截图，只写可见数据，不推算被截掉的总数或commit；如果没有访问线上运行或无法关联源码版本，明确保留该缺口。已有图片只读，不修改或重新制作成功截图。

## 报告与可追溯性

- 记录skill版本、实际读取的代码位置和本次执行范围。使用次数按完成的审查任务计，同一任务反复读文件不增加次数。
- 版本修订基于真实使用反馈；保留修改前快照和变更原因，不补造过去的日期、commit、用户调用或测试执行记录。
- 区分当前实现和业务批准状态。费用/订单/授权规则未确认时标记 `needs_human_review`，不因测试断言存在就升格为已批准。
- 只在用户授权范围内生成报告；不要为增强证据自行触发CI、执行Vitest、联网调用模型、写数据库或修改业务代码。
