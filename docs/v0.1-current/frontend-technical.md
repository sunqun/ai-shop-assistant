# 前端交互与技术文档

> 本文为 v0.1 实现快照；对话下单流程已由 [v0.2 单一自动流程](../v0.2-unified-shopping/frontend-technical.md) 取代。

更新日期：2026-11-21。本文记录当前桌面网页的页面结构、交互、状态和接口协作，不提出界面改版。

相关文档：[需求功能清单](requirements-list.md)、[后端技术文档](backend-technical.md)。实现依据为当前工作区代码；本次文档整理未执行界面或自动化用例。

## 1. 技术结构与路由

- Next.js App Router、React、TypeScript；页面交互主要通过客户端组件与服务端HTTP接口协作。
- 全局组件：SiteHeader、LanguageProvider、AuthProvider、ToastProvider。页面不直接调用数据库或内部业务工具。
- 样式由 app/globals.css 引入共享、目录、助手、购物车、商品详情、反馈和窗口断点文件；/assistant 单独加载 assistant.css。
- 顶部“订单”导航对应 /orders，本人订单和账户授权都在此页；当前没有独立 /me 页面。

| 页面 | 目的 | 主要组件/文件 |
| --- | --- | --- |
| / | 浏览商品，使用只读AI搜索 | app/page.tsx、components/home、components/assistant-docker |
| /products/detail?productId=… | 查看单商品与评论、选择数量 | productGallery、productInfo、reviews |
| /cart | 编辑普通购物车、核对报价和建单 | app/cart/page.tsx、lib/cart-client |
| /assistant | 购物对话、任务控制和评论分析 | useAssistant、AssistantMessages、AssistantComposer、ShoppingWorkflow、AssistantReviewAnalysis |
| /orders | 本人订单和建单同意入口 | OrderCard、AuthorizationPanel |
| /handoff?token=… | 查看短链商品并展示交接提交入口 | app/handoff/page.tsx |
| /login | 兼容路由，直接重定向首页 | app/login/page.tsx；登录使用全局弹窗 |

## 2. 页面布局与信息顺序

### 2.1 首页

目的：用户先筛选和浏览目录，也可用右侧AI表达商品需求。

| 区域 | 位置和信息顺序 | 操作与提醒 |
| --- | --- | --- |
| 全局导航 | 页面顶部：站点、商品/订单/AI助手/购物车入口、语言与登录状态；优惠为非阻塞提示 | 登录由用户主动触发；进入首页不自动弹登录框。 |
| 分类筛选 | 商品区域左侧，分类名称与数量 | 切换分类重新获取第一页。 |
| 商品工具条 | 结果区域顶部，结果标题、关键词框、清除操作和排序 | 推荐/评分/价格排序提交服务端，不能只对已加载商品排序。 |
| 商品网格 | 中间主区域，卡片依次包含名称、公开规格/评分、价格、库存和加购 | 卡片名称可进入详情；加购有处理中及完成反馈，缺货不能作为有货加购。 |
| 续页区 | 商品网格底部 | 显示加载更多或失败重试；失败保留已加载结果。 |
| 短链列表 | 右侧栏顶部，仅有有效短链时显示 | 显示商品、数量、创建人和链接；复制、打开、删除。 |
| AI搜索面板 | 右侧短链区域下方；标题、查询输入、历史摘要、结果/澄清 | 当前输入框在面板结果区上方；结果独立滚动，面板不遮盖中间目录。 |

~~~text
┌────────────────── 导航 / 优惠提示 / 账户 / 语言 ──────────────────┐
│ 左侧分类     │ 商品工具条：关键词 / 排序        │ 短链列表（有则显示）│
│ 分类及数量   │ 商品卡  商品卡  商品卡           │ 商品 / 数量 / 操作 │
│              │ 商品卡  商品卡  商品卡           ├───────────────────┤
│ 独立滚动     │ 结果滚动 / 续页 / 重试           │ AI标题 / 查询输入  │
│              │                                  │ 历史摘要 / 结果卡  │
└──────────────┴──────────────────────────────────┴───────────────────┘
~~~

当前首页助手为占位面板；没有收起、拖动小精灵或全站自动悬浮的交互。样式中存在的预留类名不作为功能已实现依据。

### 2.2 商品详情

目的：核对具体商品公开信息，选择件数并加入普通购物车。

- 页面头部为商品名称、说明及返回入口。
- 主区域左侧商品视觉区；右侧依次为品牌/分类、价格、评分/可用库存、规格、数量和加购按钮。
- 评论放在详情后续内容区，展示详情接口返回的首批评论；当前Reviews组件没有继续加载入口，后端评论分页能力不等于详情页已能浏览全部评论。
- 价格和库存放在主要加购操作附近；缺货或加购中禁用相应操作，失败使用现有提示，不编造库存承诺。

~~~text
┌────────────────── 商品名称 / 说明 / 返回 ──────────────────┐
│ 商品视觉区（吸顶）             │ 品牌 / 名称 / 价格           │
│                               │ 库存 / 评分 / 规格           │
│                               │ 数量选择 / 加入购物车        │
├───────────────────────────────┴─────────────────────────────┤
│ 评论首批：公开昵称掩码 / 评分 / 内容 / 日期                    │
└─────────────────────────────────────────────────────────────┘
~~~

### 2.3 普通购物车

目的：明确商品、数量、分配结果和总费用，再由用户提交订单。

- 左列商品行：图标/名称、SKU/品牌、单价、请求数量、商品行金额和移除操作；库存分配和缺货提示与对应商品关联。
- 右列报价摘要：商品小计、优惠、运费、总额、建单授权提醒及提交入口。
- 修改商品使旧报价失效，前端重新同步购物车与报价，不自行确定价格或优惠。
- 商品资料按实际ID分批读取；目录读取失败和商品不可读单独提示，不能展示为“空购物车”。
- 提交中锁定重复提交入口；成功展示订单记录和购买摘要，不展示未实现的真实支付结果。

~~~text
┌────────────── 商品清单 ──────────────┬──────── 金额摘要 ────────┐
│ 名称 / SKU / 单价                   │ 商品小计                 │
│ 请求数量 / 可分配量 / 缺货量         │ 优惠 / 运费              │
│ 数量输入 / 移除 / 行金额             │ 总额                     │
│ …                                   │ 登录/授权提醒 / 提交按钮  │
└─────────────────────────────────────┴──────────────────────────┘
~~~

### 2.4 AI购物对话页

目的：完成单商品多轮需求澄清、选品、报价、任务控制及当前商品评论分析。

- 顶部：在线标识、manual/auto模式切换和重新开始；活动任务期间模式切换和重置受状态限制。
- 主体左列对话区：用户原话、候选、澄清问题、报价、评论报告、订单或短链结果。
- 报价卡展示任务保存的真实件数、小计、优惠、运费和总额；任务状态、倒计时、取消和确认入口与卡片关联。
- 对话底部为输入框及当前操作；消息区独立滚动，输入不随消息列表移出工作区。
- 右侧270px流程说明，顺序为搜索、选择商品、生成金额、确认或自动创建订单；显示当前阶段。
- 评论报告显示读取/分析数量、总量、完整/部分状态、优点/缺点/分歧、原文引用及继续/刷新操作。评论引用不能充当下单指令。

~~~text
┌──────── AI在线 ───── 模式：确认后下单 / 自动下单 ── 重新开始 ──┐
│ 用户原话 → 候选商品 → 澄清问题/报价            │ 购物流程        │
│ 商品名称 / 规格 / 库存 / 数量                 │ ① 搜索          │
│ 小计 / 优惠 / 运费 / 总额                     │ ② 选品          │
│ 当前状态 / 倒计时 / 确认 / 取消               │ ③ 报价          │
│ 评论报告 / 读取进度 / 原文引用                │ ④ 建单          │
│ ────────── 独立滚动的消息区域 ──────────      │ 当前阶段        │
├──────────────────────────────────────────────┤                 │
│ 输入需求、补槽答案、进度或评论问题 / 当前操作  │                 │
└──────────────────────────────────────────────┴─────────────────┘
~~~

### 2.5 本人订单与授权

目的：查看已保存的购买内容及建单同意状态。

- /orders 顶部是订单数量/登录提示和继续购物入口，其后为授权区与订单列表。
- 未授权用户在授权区明确勾选后保存；已授权状态不再显示待授权复选框，不提供撤销入口。
- 订单卡按来源、订单组编号、创建时间、商品名称、SKU、数量、行金额和总额排列；展开后显示小计、优惠和运费。
- 商品名称使用订单创建时快照；无快照显示明确的历史名称缺失文案。
- 未登录、加载中、无订单分别呈现；没有履约、支付和退款状态筛选。

### 2.6 登录/注册弹窗与交接页

登录/注册弹窗位于全局遮罩中，表单顺序为模式、用户名、密码，注册增加确认密码。登录时按授权状态提供默认不勾选的建单同意选项；注册不自动授权。错误放在表单附近，提交中禁用重复提交。

交接页顺序为标题与返回、创建人、单商品、数量/单价/商品金额、“支付密码”输入和确认下单按钮；成功结果显示订单编号及费用明细。

~~~text
登录弹窗                              交接页
┌──── 登录 / 注册 ──── 关闭 ┐        ┌──── 确认订单 / 返回首页 ────┐
│ 用户名                    │        │ 创建人 / 商品名             │
│ 密码 / 注册确认密码       │        │ 数量 / 单价 / 商品金额      │
│ 建单同意（适用时）        │        │ 支付密码输入 / 确认下单     │
│ 错误提示 / 提交           │        │ 成功后：编号 / 费用明细     │
└───────────────────────────┘        └─────────────────────────────┘
~~~

交接页现有输入框不构成真实支付密码验证；匿名提交权限及支付规则为 needs_human_review。不得把页面存在视为支付能力已完成。

## 3. 桌面窗口、宽度、分栏与滚动

以下记录实际样式及维护时的布局约束；本次未做浏览器尺寸验收。

| 区域 | 当前实现与维护约束 |
| --- | --- |
| 共享内容区 | 常规页面内容宽度为 min(1200px, 100% − 48px)。首页宽窗口为 min(1440px, 100% − 64px)。 |
| 首页分栏 | 宽窗口：主区 + 340px助手列，主区为190px分类 + 弹性结果；861–1200px样式使用310px助手、150px分类和两列商品卡。最终值受样式引入顺序约束。 |
| 首页高度 | 大于860px时按首屏高度组织，顶栏与内容分开，分类和商品结果各自滚动；结果工具条和分类标题在各自滚动区顶部吸顶。 |
| 商品网格 | 宽窗口三列，中等桌面窗口两列，单元使用 minmax(0, 1fr)，商品名可截断且详情可达。 |
| 详情 | 两列 minmax(0, 5fr) 和 minmax(340px, 7fr)，视觉区 top:88px 吸顶；文字内容不挤压购买区。 |
| 购物车 | 主列表 + 320px摘要列，较窄桌面断点摘要为260px；摘要 top:88px 吸顶。 |
| 购物对话 | 高度取当前视口扣除导航和边距；主区为弹性对话列 + 270px说明列，消息区滚动，输入保持可见。 |
| 订单与短链 | 卡片使用已有栅格；短链列表局部滚动、长链接截断，完整地址通过标题/复制获取。 |

维护规则：

- 桌面窗口调整时先收缩弹性列和商品网格，保留必要操作宽度；既有较窄断点沿用，不新增移动端页面方案。
- 可滚动的flex/grid子区保持 min-width:0、min-height:0；长消息与评论换行，长商品名和链接按组件规则截断。
- 吸顶元素只在所属滚动区定位，层级不得盖住输入、确认、取消和错误提示；模态弹窗独立处理焦点与关闭。
- 整页不依靠横向滚动才能操作；密集信息优先换行或局部滚动，不用溢出隐藏掩盖关键按钮。
- 维护后应在1440、1280、1024px及短高度桌面窗口检查可操作性；这些是布局约束，不代表本次已验证。

## 4. 状态与异步交互

| 状态 | 呈现及处理 |
| --- | --- |
| 加载 | 首次商品、详情、订单、短链读取展示对应加载；新查询清理旧商品，避免旧结果冒充当前结果。 |
| 空数据 | 无商品给筛选调整入口；无订单给继续购物入口；无评论说明缺少依据；无短链不显示短链区。 |
| 失败 | 首屏目录有重新加载，续页失败保留当前列表并按原游标重试；助手给错误或重连入口；页面不能据断网断定订单未创建。 |
| 权限不足 | 登录弹窗和授权区引导完成必要条件；401/403不能靠修改前端状态绕过。 |
| 处理中 | 加购、删除短链、保存授权、提交订单和发送消息分别有禁用/加载状态；不重复触发相同操作。 |
| 待澄清 | 候选与问题一起显示；数值回答可补槽；未知必需条件不能通过“就这款”跳过。 |
| 自动待提交 | 显示报价和约3秒倒计时；服务端仍以commitAfter和reviewHold决定能否推进。 |
| 评论分析中/部分 | 显示读取与分析进度及完整性；可继续或明确刷新，不把部分分析描述成全部结论。 |
| 结果待核对 | 保留原任务和恢复操作，不重新生成另一笔交易。 |

- 首页查询使用请求代际标识隔离旧响应；续页按游标防重复请求并按商品ID去重。
- useAssistant 按用户和任务隔离响应，用revision避免旧任务视图回退；sessionStorage只缓存当前用户任务ID，权威任务状态在后端。
- canSend 根据发送、恢复、提交、取消和连接状态决定；活动任务期间仍可发送进度、评论等消息，搜索修改可能被服务端拒绝。
- 确认携带当前taskId、quoteId和cartVersion；服务端返回的canConfirm/canCancel/canRecover等能力位决定按钮可用性。

## 5. 关键流程

~~~mermaid
flowchart TD
  A[用户发送消息] --> B[服务端统一意图解析]
  B --> C{动作}
  C -->|搜索或补槽| D[搜索和候选核实]
  D --> E{仍需澄清}
  E -->|是| F[显示问题并等待回答]
  F --> A
  E -->|否| G[商品 数量 报价]
  G --> H{模式}
  H -->|manual| I[明确确认并携带当前报价]
  H -->|auto| J[等待commitAfter且未暂停]
  I --> K[服务端建单]
  J --> K
  C -->|评论或状态| L[显示报告或进度]
  C -->|精确取消命令或按钮| M[服务端检查可取消阶段]
  M --> N[停止直接建单并返回短链结果]
  K --> O[订单回执或原任务结果核对]
~~~

## 6. 接口协作

| 场景 | 前端调用 | 关注字段 |
| --- | --- | --- |
| 目录和详情 | GET /api/v1/products、/categories、/products/detail | products、nextCursor、product、reviews |
| 普通购物车 | GET /api/v1/carts；POST /carts/reconcile、/carts/quote、/carts/order | allocations、cartVersion、expiresAt、quoteId、费用和订单编号 |
| 首页助手 | POST /api/v1/assistant/search | query、sessionId、cursor；返回摘要、routing、商品与澄清 |
| 购物消息 | POST /api/v1/assistant/messages | query、mode、idempotencyKey、taskId、quote；返回task、reply、routing及评论报告 |
| 任务 | GET /api/v1/assistant/tasks 与 /tasks/[taskId]；POST /tasks/[taskId]/[action] | revision、phase、能力位、commitAfter、reviewHold |
| 本人订单/授权 | GET /api/v1/me/orders；POST /api/v1/me/authorization | orders、consent、user |
| 短链 | GET/POST /api/v1/assistant/payment-links；DELETE /payment-links/[linkId]；GET/POST /api/v1/handoff | linkId、urlToken、product、quantity及交接结果 |

完整的服务端边界和未确认规则见[后端技术文档](backend-technical.md)。前端显示的金额、库存和状态以本次服务端响应为准。
