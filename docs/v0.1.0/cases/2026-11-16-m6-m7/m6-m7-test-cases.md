# M6/M7 订单记录测试用例

范围：点击结账页“付款”创建一条订单记录并原子扣减对应的已锁库存；“我的”只展示当前用户的订单记录。不接入支付渠道或资金扣款，不执行物流、发货、收货、退款、退货或其他履约流程。

| 编号 | 场景 | 预期结果 | 验证方式 |
| --- | --- | --- | --- |
| M6-T01 | 未登录用户提交建单请求 | 返回 401，不创建订单 | API 集成测试 |
| M6-T02 | 已登录但未授权用户提交建单请求 | 返回 403，不创建订单 | API 集成测试 |
| M6-T03 | 已授权用户以有效购物车、报价和 ACTIVE 库存预留点击“付款” | 同一事务写订单及商品明细，按分配数量减少 `on_hand` 和 `reserved`，预留转为 `CONSUMED` 并写事件，返回订单编号 | MySQL 集成测试与页面流程 |
| M6-T04 | 同一用户用相同幂等键和参数重复提交 | 返回同一订单，不新增记录、不重复扣减库存或写消费事件 | MySQL 集成测试 |
| M6-T05 | 同一幂等键改用不同购物车、版本或报价 | 返回冲突，不新增记录 | MySQL 集成测试 |
| M6-T06 | 购物车版本/有效期、报价有效期、商品价格或预留状态/数量/有效期校验失败 | 建单失败，库存、预留和订单均无部分变更 | MySQL 集成测试 |
| M6-T08 | WEB 或 AI 下单时 SKU 库存预留由有效转为过期/被消费 | 只能有一个事务成功；失败事务不得创建订单或重复消费库存 | 并发 MySQL 集成测试 |
| M6-T07 | 查看成功回执和订单详情 | 展示订单编号、商品摘要、金额快照和创建时间，不显示支付或履约状态 | 页面/API 验证 |
| M7-T01 | 当前用户打开“我的”订单列表 | 只按创建时间倒序展示本人已落库订单；无记录时显示空状态 | API 集成测试与页面流程 |
| M7-T02 | 未登录用户读取订单列表或详情 | 返回 401 | API 集成测试 |
| M7-T03 | 用户尝试读取他人订单详情 | 不返回订单数据，返回 404 | API 集成测试 |
| M7-T04 | 订单列表请求失败后重试 | 显示错误和重试入口，重试后更新列表状态 | 页面测试 |

执行记录：本轮结果见 `docs/v0.1.0/cases/2026-11-16-inventory-consume/test-cases.md`。数据库集成场景要求配置可用 MySQL；没有数据库时记录为“未执行”。
