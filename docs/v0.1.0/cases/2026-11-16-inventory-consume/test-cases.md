# 付款消费库存专项测试用例

范围：WEB 与 AI 下单共用订单事务；付款成功时消费有效库存预留，减少 `inventory_skus.on_hand` 与 `reserved`，将预留标记为 `CONSUMED` 并写入消费事件。不接入支付渠道或资金扣款。

| 编号 | 前置数据 | 操作 | 预期结果 | 验证方式 |
| --- | --- | --- | --- | --- |
| INV-T01 | 有效购物车、报价和 `ACTIVE` 预留，预留数量与订单分配一致 | 提交付款 | 订单创建成功；`on_hand` 与 `reserved` 各减少分配数量；预留为 `CONSUMED`；写入 `CONSUMED` 事件 | MySQL 集成测试 |
| INV-T02 | 同一有效幂等键已成功建单 | 使用相同幂等键重试付款 | 返回原订单；库存、预留和消费事件不重复变化 | MySQL 集成测试 |
| INV-T03 | 预留已过期、状态非 `ACTIVE` 或数量不匹配 | 提交付款 | 请求失败且订单、库存、预留和事件全部回滚 | MySQL 集成测试 |
| INV-T04 | WEB 来源购物车有有效预留 | 通过网页结账付款 | 走统一库存消费路径并完成扣减 | API/页面验证 |
| INV-T05 | AI 来源购物车有有效预留 | 通过 AI 下单付款 | 走统一库存消费路径并完成扣减，订单来源保持 `assistant` | API 集成测试 |
| INV-T06 | 两个并发请求竞争同一预留 | 同时提交付款 | 只有一个事务成功；另一个失败且不创建订单、不重复消费库存 | 并发 MySQL 集成测试 |
