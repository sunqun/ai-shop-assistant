# M2 首页商品列表与加购测试用例

## 范围

验证首页 `/` 商品列表、搜索筛选、详情规格与数量、购物车查看编辑移除，以及右侧助手占位；`/products` 列表路由必须不存在，商品详情仍使用 `/products/:productId`。

## 用例

| 编号 | 前置条件 | 操作 | 预期 |
| --- | --- | --- | --- |
| M2-T01 | 浏览器打开商城 | 进入 `/`，点击任一有库存商品的名称 | 进入 `/products/:productId` 详情页，显示价格、规格、库存和数量控件 |
| M2-T02 | 详情页商品有库存 | 选择规格，数量设为 2，点击“加入购物车” | 购物车保存该商品、所选规格和数量 2，按钮显示成功状态 |
| M2-T03 | 购物车已有商品 | 刷新 `/cart` | 商品、规格、数量和小计仍可见 |
| M2-T04 | 浏览器本地购物车包含无效 JSON | 返回首页点击有库存商品加购 | 页面不崩溃，购物车被恢复为合法数据并加入当前商品 |
| M2-T05 | 购物车有商品 | 修改数量后移除一行 | 数量、小计和费用摘要即时更新，移除项不再显示 |
| M2-T06 | 商品列表页 | 输入关键词、切换品类和价格排序 | 商品列表按条件更新；无匹配时保留条件并显示原位空状态 |
| M2-T07 | 首页桌面窗口宽度 >= 1200px | 进入首页并收起助手 | 展开时助手占据右侧固定列且不遮挡商品；收起后入口可拖动且仍在视口内 |
| M2-T08 | 任意页面 | 访问 `/products` | 不生成列表页面；应用显示未找到页面，商品详情 `/products/:productId` 仍可用 |

## 执行命令

```powershell
npm run typecheck
npm run build
```

## 执行记录

- `npm run typecheck`：通过。
- `npm run build`：通过；Next.js 路由清单包含 `/`、`/cart`、`/products/[productId]`，不包含 `/products`。
- 浏览器交互验证（2026-11-15，ChatGPT in-app browser）：
  - M2-T01：通过，首页商品名称可进入 `/products/desk-kit` 详情页，详情页显示价格、规格、库存和数量控件。
  - M2-T02：通过，选择 `USB-C 扩展`、数量 2 后加购，按钮显示“已加入购物车”，购物车保存所选规格和数量。
  - M2-T03：通过，重新进入 `/cart` 后本地商品、规格、数量和小计仍可恢复。
  - M2-T05：通过，购物车数量从 2 改为 3 后小计即时更新，移除后显示空购物车。
  - M2-T04：代码路径验证；首页加购读取本地购物车时捕获 JSON 解析异常并恢复为空数组，随后写入当前商品。当前 CUA 浏览器隔离环境无法直接写入页面 `localStorage`，因此未完成真实损坏 JSON 的端到端注入。
  - M2-T06：通过；输入“耳机”后仅显示耳机商品，切换“办公数码”后显示 3 件办公数码商品，选择“价格由低到高”后商品按价格升序排列，输入不存在的关键词后显示原位空状态并保留搜索条件。
  - M2-T07：通过收起入口拖动验证，入口可从右下角移动到视口内其他位置；当前 in-app browser 视口约为 623×613，助手已按 CSS 使用独立右侧布局列。由于当前环境没有可用的独立 Chrome 控制面板，尚未完成 >= 1200px 实际窗口截图复核。
  - M2-T08：通过，访问 `/products` 显示 Next.js 404，商品详情 `/products/[productId]` 仍可用。
- 遗留验证：M2-T04 仍缺少损坏 `localStorage` JSON 的真实浏览器注入，M2-T07 仍缺少 >= 1200px 独立桌面窗口截图复核；对应实现已完成类型检查和生产构建。
