# M1 注册功能测试用例

## 环境

- 项目：`C:\document\ai-shop`
- 页面：`http://localhost:3003/`（API 联调用临时开发端口 `3010`）
- 数据库：本地 MySQL，使用项目 `.env` 连接；测试用户名使用随机前缀，避免污染已有账号。

## 用例

| 编号   | 前置条件              | 操作                                                                  | 预期结果                                                                   | 关联  |
| ------ | --------------------- | --------------------------------------------------------------------- | -------------------------------------------------------------------------- | ----- |
| M1-T12 | 首页已打开，未登录    | 点击“登录”，切换为注册，填写唯一用户名、至少 8 位密码和确认密码并提交 | 返回 201；弹窗关闭；首页路由不变；建立 session；用户 `is_authorized=false` | AC-21 |
| M1-T13 | 注册弹窗处于注册模式  | 输入少于 8 位密码提交                                                 | 弹窗保留，显示密码长度错误，不创建用户                                     | AC-21 |
| M1-T14 | 用户名已存在          | 用相同用户名再次注册                                                  | 返回 409 `USERNAME_ALREADY_EXISTS`；弹窗保留；不创建重复用户               | AC-21 |
| M1-T15 | 注册成功              | 查询用户记录                                                          | `userid` 为服务端生成 UUID；数据库只保存密码哈希；授权字段为 false         | AC-21 |
| M1-T16 | 注册弹窗处于注册模式  | 切换回登录或注册失败                                                  | 模式可切换；失败不跳转、不清空用户名和密码输入                             | AC-21 |
| M1-T17 | 注册成功并保留 cookie | 调用 `GET /api/v1/auth/session`                                       | 返回刚注册用户，`isAuthorized=false`                                       | AC-21 |

## 执行记录

- `npm run typecheck`：通过。
- `npm run build`：通过，包含 `/api/v1/auth/register` 路由。
- 注册 API 合法输入：通过，返回 201、用户摘要和 `Set-Cookie`。
- 注册 API 短密码：通过，返回 400，未写入用户。
- 注册 API 重复用户名：通过，返回 409 `USERNAME_ALREADY_EXISTS`。
- 注册后 session：通过，带 cookie 调用 session 返回同一用户且未授权。
- 浏览器页面点击和视觉回归：本次未用 Playwright 执行；组件静态检查由 TypeScript 和 Next build 覆盖。
