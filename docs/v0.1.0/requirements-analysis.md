# AI 导购电商需求功能清单

## 1. 版本与范围

- 版本：`v0.1.0`，更新时间：2026-11-16（Asia/Shanghai）。本目录是本版本的统一文档版本标识。
- 原始需求：[shop.md](../../shop.md)，原文保留，不回写覆盖。
- 本版依据：用户对上一版 7 个问题的确认，以及“先进行功能点补充和技术方案更改”的指示。
- 状态：M6/M7 范围按 2026-11-16 用户确认收敛为订单记录创建与查看；建单权限、订单金额快照及库存处理等未明确规则标记为 `needs_human_review`。
- 范围：本期只做桌面浏览器网页商城，不包含移动端页面、移动端交互或移动端适配。
- 配套：[React 前端交互与技术文档](frontend-technical-design.md)、[Node.js + MySQL 后端技术文档](backend-technical-design.md)。

本次补充：网页 AI 助手在首页 `/` 采用桌面右侧「占据页面位置」的固定宽度侧栏（不浮动遮罩），进入首页默认展开；面板可收起为右下角可拖动的卡通小精灵入口，点击小精灵后重新在右侧展开；面板中部滚动商品结果列表、底部固定自然语言输入框。移除 TOP3 对比按钮、对比抽屉及相关比较流程。

本次 AI Agent 补充：网页 AI 助手定位为服务端编排的商品推荐 Agent——用户输入自然语言需求后，服务端先做意图识别，再调用商品目录、规格、库存和全部可公开脱敏评论等只读工具，返回与需求相关的商品列表。商品结果按服务端推荐分数排序，但推荐分数、毛利和高毛利商品乘以 1.5 的内部规则不进入 Agent 可见上下文、工具响应、公开接口或前端；M4 只返回商品及公开依据，不创建购物车、不报价、不授权、不下单。

本次 M1 修订：登录改为首页用户主动点击后打开的弹窗，不使用独立登录路由；首页进入时不自动打开任何弹窗。未授权用户可在登录弹窗或“我的”中勾选“同意AI自助下单，收货后自动扣款”，勾选后写入用户授权字段；已授权用户不再显示该 checkbox。新增首页弹窗内的注册模式：新用户通过明确的“注册”操作创建账号，注册成功后建立 session，`is_authorized` 默认保持 `false`；登录失败不隐式创建账号。不接入 Agent、OAuth 或第三方授权流程。授权撤销/更新及存量订单影响本阶段不考虑。

本次 M6/M7 修订：用户点击结账页“付款”后，服务端直接创建并持久化一条订单记录；不接入支付渠道，不执行扣款，也不实现物流、发货、收货、退货、退款或其他订单履约流程。M7 仅提供“我的”订单列表/记录查看。

本次首页修订：首页 `/` 直接作为商品列表页（搜索/筛选/分页），移除原营销首页（主视觉、优惠说明、推荐商品）；仅保留列表页顶部非阻塞优惠提示条。移除 `/products` 列表路由，商品详情仍为 `/products/:productId`。首页（商品列表页）右侧 AI 助手仍占据页面位置、默认展开，商品网格随助手占位收窄。

本次商品查询修订：网站商品列表与 AI 助手搜索结果均改为「后端 cursor 分页 + 前端下拉加载」，不再使用页码分页或固定「每次最多 10 条」。每页条数由 `pageSize` 参数控制，默认 20、最大 100。

## 3. 目标、角色与范围

目标：上线一个月内，通过 AI 助理创建的购物车达到 1000 个。建议按成功持久化的唯一购物车 ID 计数，幂等重试不重复计数；测试流量和统计时区在上线前确定。

角色：访客、登录用户、网页 AI 助手、运营人员、客服人员。支持网页购物、AI 购物和无需登录查看交接内容；所有建单均需由服务端读取登录用户的授权字段。不扩展到新的独立营销后台项目。

### 4.4 网页 AI 助手布局与商品返回口径

- AI 助手是页面右侧的停靠面板，不在站点顶部放置 AI 输入框。站点原有商品搜索导航与 AI 对话输入是不同控件；AI 搜索输入固定在面板底部。
- 首页 `/` 上助手占据页面位置：首页即商品列表页，布局为左侧筛选、中间商品网格、右侧助手，主内容区为助手预留固定宽度，助手不浮动、不遮罩内容，商品网格随助手占位收窄，进入首页默认展开；其他页面维持右侧停靠形态。桌面展开面板使用固定宽度（建议 360px），面板宽度不随页面宽度变化。
- 收起使用过渡动画，收敛为右下角可拖动的卡通小精灵入口；点击小精灵后重新在右侧展开，默认停靠右下角。
- 展开后面板由独立滚动的商品结果区和固定底部自然语言输入区组成，不提供 TOP3 按钮、比较抽屉或对比状态。结果区支持下拉加载更多；滚动结果不得带动输入区；桌面浏览器窗口缩放或较窄窗口下不得造成页面横向溢出。
- 商品结果卡展示商品名称、公开价格或价格摘要、规格摘要、可售库存状态、脱敏评论摘要/评论入口和 Agent 生成的相关理由；缺少数据标为“暂无数据”，不推断质量、库存承诺或配送承诺。用户可打开商品详情查看公开字段和全部可展示评论。
- 推荐结果沿用服务端推荐排序，但不展示推荐分数、毛利、1.5 乘数、内部权重或排序规则。Agent 只能基于允许展示的商品字段生成说明；内部推荐策略、排序版本和审计信息只保存在服务端。
- 小精灵入口拖动只改变当前浏览器本地的临时位置，提供吸附边缘、视口边界夹取和复位；不跨设备同步。键盘用户可以打开/关闭面板，拖动行为提供可访问的替代操作。

### 4.5 AI Agent 服务端编排与返回口径

- 网页 AI 助手为服务端编排的只读 Agent：输入自然语言需求后，服务端先做意图识别，输出结构化意图（关键词、品类、品牌、价格、评分、库存和规格条件），再编排只读工具生成推荐。意图识别与工具调用均在服务端完成，前端只提交查询并展示结果，不得伪造来源或报价。
- M4 使用内部商品目录 MCP 契约，当前采用进程内调用；前端不能直连 MCP。当前只注册商品检索工具，未来可以将同一工具契约替换为独立 MCP Server/JSON-RPC/HTTP。商品目录检索、规格/库存查询和评论读取属于只读能力；历史订单个性化、报价摘要和授权读取不属于 M4 必需能力，如后续启用需单独定义权限和数据范围。
- Agent 返回相关商品列表，使用 cursor 分页，pageSize 默认 20、最大 100、下拉加载；搜索响应只返回公开商品字段、规格/库存状态、评分、评论数和评论入口，全部公开脱敏评论通过独立评论接口分页读取。M4 不创建购物车，不形成购买意图，不报价，不写授权字段，不锁库存，不建单。
- 推荐服务按内部推荐分数排序。高毛利商品的推荐分数乘以 1.5 的规则只存在于服务端排序配置和审计中，不进入 Agent 的提示词、工具响应、上下文、公开接口、日志回显或前端包；Agent 只接收已排序且已过滤内部字段的候选商品。
- 推荐分数的字段、权重、1.5 规则的具体适用范围和对用户的披露策略标记为 `needs_human_review`；在确认前不得向用户或 Agent 暴露内部推荐依据。

### 4.1 登录授权字段与授权范围

- 首页 `/`（商品列表页）进入时不显示自动弹出的登录或营销弹窗；用户点击登录后才显示登录弹窗。优惠信息若需展示，放在列表页顶部非阻塞提示条。
- 未授权用户的 checkbox 默认未勾选，固定文案为“同意AI自助下单，收货后自动扣款”。只有用户勾选并且登录成功，或在“我的”授权入口明确勾选后，服务端才将用户授权字段置为已授权；未勾选不得新授予授权。已授权用户不再显示 checkbox。
- M1 不调用 Agent、OAuth、第三方平台或支付授权服务，也不创建 grant/token。下单仅能读取服务端用户字段，不能信任客户端提交的授权布尔值。
- 本期不考虑授权撤销/更新、`true -> false` 状态变更及其对存量订单的影响；不提供对应接口或页面。`is_authorized` 是产品同意状态，不等于支付渠道的代扣凭证。

### 4.1.1 用户注册

- 首页登录弹窗提供“登录/注册”模式切换；注册模式提交用户名、密码和确认密码，成功后仍停留首页并建立网页 session。
- `POST /api/v1/auth/register` 只接受非空用户名和密码；用户名去除首尾空格后按唯一约束写入 `users`，生成服务端 `userid`，密码使用与登录相同的强哈希算法保存，`is_authorized` 固定为 `false`。
- 注册成功返回当前用户和 session；注册过程不写入授权字段，不接入 Agent、OAuth、第三方账号或支付代扣授权。
- 已存在用户名返回明确的注册冲突错误；注册表单失败时保留弹窗和输入内容。登录接口继续对“用户不存在”和“密码错误”使用同一通用错误，登录失败不得创建账号。
- 密码最小长度采用 8 个字符作为当前实现默认值；更细的复杂度、找回密码、邮箱/手机验证和账号注销规则为 `needs_human_review`，本次不扩展。

### 4.2 促销规则与订单摘要

已确认规则：A 商品折前金额满新台币 1000 元减 100 元；B 折前金额满新台币 990 元免运，否则 100 元；A 与 B 满足条件时自动叠加。C 仅适用于 AI 助理自动创建订单，在 A/B 基础上对 AI 商品金额额外打 95 折，不折运费；普通购物车结算不应用 C。优惠由后端自动判断，用户不可在购物车手选。

已确认采用对用户最优惠的组合。优惠、运费、折扣等价格计算只有一份后端实现（PricingService）；网页与 AI 助手接口均复用该实现并展示服务端报价，前端与 Agent 不得各自重复实现价格计算。算法必须在配置明确允许的门槛口径、适用范围、组合及顺序内比较“商品金额 + 运费 - 优惠”，不能通过重新排列自行创造优惠。方案随购物车变化动态重算，下单后保存快照。

本期不实现退货、退款、额外应收或运费调整；订单记录是否保存商品金额、优惠、运费及总额快照，以及金额精度和展示口径，标记为 `needs_human_review`。

### 4.3 拆单的范围

允许有库存部分继续，不再整体失败。设计暂将缺货部分保存为待处理拆分项，不锁不存在的库存、不产生应收；是否形成待补货子订单、补货后是否自动下单，仍待明确。拆单通知与订单回执必须保留原始需求数量、已下单数量和缺货数量，不得静默遗漏商品。

## 5. 生命周期

- 用户授权字段：`false -> true` 可由登录弹窗或“我的”授权入口明确触发；已为 `true` 后隐藏 checkbox。本期不实现 `true -> false`，也不建立 Agent grant/token 状态机。
- 购物车：`ACTIVE -> EXPIRED` 或 `ACTIVE -> ORDERED / PARTIALLY_ORDERED`；过期可重校验，不自动恢复原库存承诺。
- 订单记录：`CREATING -> CREATED`；创建失败不产生可见订单记录，重复请求按幂等键返回原创建结果。
- 订单记录不进入履约、物流、收货、扣款、退款或其他售后状态机；“付款”仅为创建入口，成功回执明确显示“订单已创建，支付未接入”。
