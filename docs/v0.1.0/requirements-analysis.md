## 3. 目标、角色与范围

目标：上线一个月内，通过 AI 助理创建的购物车达到 1000 个。建议按成功持久化的唯一购物车 ID 计数，幂等重试不重复计数；测试流量和统计时区在上线前确定。

角色：访客、登录用户、用户授权的 AI 助理、运营人员、客服人员。支持网页购物、AI 购物和无需登录的交接结账；不扩展到新的独立营销后台项目。

### 4.4 网页 AI 助手布局与对比口径

- AI 助手是页面右侧浮动面板，不在站点顶部放置 AI 输入框。站点原有商品搜索导航与 AI 对话输入是不同控件；AI 搜索输入固定在面板底部。
- 桌面展开面板使用固定宽度（建议 360px）；以侧栏形式在页面右边缘展开，面板宽度不随页面宽度变化。收起使用过渡动画，成为可拖动的卡通入口，默认停靠右下角。面板可由入口重新打开。
- 展开后面板分为固定 TOP3 比较区、独立滚动的搜索结果区和固定底部输入区。滚动结果不得带动比较区或搜索区；桌面浏览器窗口缩放或较窄窗口下不得造成页面横向溢出。
- TOP3 暂按当前搜索结果的前三个商品生成，按 1～3 对齐展示；少于 3 个时展示实际命中数量，不补造商品。支持直接从比较区打开商品详情，列表保留完整搜索结果。
- 建议对比字段：当前价/可验证的到手价和优惠明细、规格/核心参数（按品类配置）、可售库存状态、预计配送信息（有可信数据时）、评分及评论数量（有数据时）。突出各商品“优势”和“需要权衡”，每条结论应能追溯到展示字段/规则；缺少数据标为“暂无数据”，不推断质量或配送承诺。
- 对比解释服务于用户，不展示毛利、内部推荐分数或 1.5 权重。TOP3 排序沿用搜索排序，但隐藏的排序因素披露仍由 Q-06 决定；界面不能声称前三就是客观质量前三。
- 入口拖动只改变当前浏览器本地的临时位置，提供吸附边缘、视口边界夹取和复位；不跨设备同步。键盘用户可以打开/关闭面板，拖动行为提供可访问的替代操作。

### 4.1 授权与优惠弹窗的区分

- 优惠弹窗是营销展示。关闭弹窗、倒计时结束、登录成功均不构成 AI 下单授权。
- 长期授权由独立、未预选的明确同意操作完成。可撤销，撤销后停止新的 AI 自动下单，既有订单按其状态处理。
- AI 下单未授权时只能提示用户，不得自动替用户同意。重复提醒以实际下单尝试为触发，避免循环弹窗。
- “AI 代下单”与“收货后自动扣款”是不同的权限；不能用前者推断用户已同意任意账户扣款。

### 4.2 促销与退货规则

原始规则保留：A 商品满新台币 1000 元减 100 元；B 满新台币 990 元免运，否则 100 元；C AI 来源订单额外 95 折。

已确认采用对用户最优惠的组合。算法必须在配置明确允许的门槛口径、适用范围、组合及顺序内比较“商品金额 + 运费 - 优惠”，不能通过重新排列自行创造优惠。方案随购物车变化动态重算，下单后保存快照。

退货后若原免运订单不再满足免运规则，需结算原规则的运费；按原规则一般为新台币 100 元，不等同于新增退货寄送费。已收过的运费不得重复收取。门槛口径、全部退货及质量原因退货等例外、拆单运费归属尚待细化，不能自动从账户扣取未确认费用。

### 4.3 拆单的范围

允许有库存部分继续，不再整体失败。设计暂将缺货部分保存为待处理拆分项，不锁不存在的库存、不产生应收；是否形成待补货子订单、补货后是否自动下单，仍待明确。拆单通知与订单回执必须保留原始需求数量、已下单数量和缺货数量，不得静默遗漏商品。

## 5. 生命周期

- 授权：`NOT_GRANTED -> ACTIVE -> REVOKED`；拒绝/跳过不影响登录，Agent token 独立轮换。
- 购物车：`ACTIVE -> EXPIRED` 或 `ACTIVE -> ORDERED / PARTIALLY_ORDERED`；过期可重校验，不自动恢复原库存承诺。
- 履约订单：`PLACED -> FULFILLING -> SHIPPED -> RECEIVED -> COMPLETED`；缺货项另行 `PENDING_STOCK`，不等同于可履约订单。
- 结算：`NOT_DUE -> DUE -> CHARGING -> PAID`，失败 `CHARGING -> FAILED`；与履约状态正交，不能因扣款失败伪装未收货。
- 退货：申请、审核、收货核验、结算调整、退款/补收；未扣款和已扣款分别处理，保留审计。

收货事件的可信来源、分批收货扣款时点、支付渠道和代扣授权仍待选定；本版只确定“先下单、收货后扣款”，不承诺已具备自动扣款能力。

| AC-13 | 订单回执清楚显示商品、规格、数量、来源、金额、优惠、运费和拆分去向。 |
