# 单一自动购物流程：需求功能清单

日期：2026-11-21。用户已在本轮对话批准以下交互及优惠 C 口径。本版本取代原任务交互模式设计。

| 编号 | 已确认要求 |
| --- | --- |
| U-01 | 对话购物只有一条自动流程，删除模式选择、请求参数、运行时字段及分支，不保留独立模型建单路径。 |
| U-02 | 用户未明确数量时默认 1 件；明确数量必须核实并贯穿库存、报价、订单和短链。 |
| U-03 | 在真实同类商品中优先选完全符合要求的有货商品；无完全匹配时返回现有服务端推荐排序最高的替代商品。排序继续使用现有毛利加权规则，不公开内部参数或分数。 |
| U-04 | 预算、品牌、评分、数值规格、自然语言条件和排除条件有差异或无法核实时，逐项说明用户要求与实际资料。不能把未知描述为符合。 |
| U-05 | 有差异时先生成有效报价，在对话记录展示商品、数量、差异、小计、优惠、运费、最终总额；输入框上方显示确认/取消操作行，不使用模态弹窗。用户接受即直接提交，无需再次输入放宽条件。 |
| U-06 | 无差异时沿用报价后约 3 秒的自动提交窗口；该窗口内仍可取消，提交开始后禁止取消。 |
| U-07 | 当前待确认任务中，“帮我下单”“确认下单”“就这款”等精确命令与确认按钮等效，都校验当前任务和已展示报价。模型分类本身不授权交易。 |
| U-08 | 取消直接下单后，按已选商品及数量生成短链。库存不足等实际提交失败应说明原因；断连或未知结果恢复原任务，不重复建单。 |
| U-09 | 优惠 C 仅授予当前 AI 对话框建立且由服务端绑定的购物任务，包括中途确认差异的任务。仅 AI 购物车来源或独立短链/网页提交不产生资格。 |
| U-10 | 不提供真实支付、扣款、物流或售后。“确认下单”不应写成已实际支付。 |
| U-11 | 取消周期状态轮询，正常操作消费接口返回结果；页面恢复和断连时按需查询，正在处理的任务可手动刷新进度。自动提交的阶段推进与截止时间保留。 |

真实数值依据缺失、相互冲突的请求、商品类型不明确或购买数量范围不明确，仍需先澄清原意。这与接受已核实商品差异不同。

测试执行、静态检查、构建和未执行的真实数据库/模型验收分别记录，不将 mock 结果当作生产验收。
