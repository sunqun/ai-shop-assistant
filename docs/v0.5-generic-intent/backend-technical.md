# 后端技术文档：通用商品检索意图

日期：2026-11-20。

## 通用契约

ProductSearchIntent 继续兼容 keywords/category/brand、预算、评分、库存与 exclude*，新增或统一为：

```json
{
  "keywords": ["背包"],
  "requiredConditions": ["防泼水"],
  "preferences": ["适合通勤"],
  "numericConstraints": [{"attribute":"重量","operator":"lte","value":1.5,"unit":"kg"}],
  "unresolvedConditions": []
}
```

属性名来自需求和商品规格键，不是代码枚举；功能为任意自然语言条件。specTerms 兼容输入由归一化转换。unresolvedConditions 由服务端记录不可信或不能从原话核实的数值条件。

## 模块拆分与执行

| 模块 | 职责 |
| --- | --- |
| lib/intent/index.ts | 模型结构化抽取、字段校验、历史合并和摘要 |
| lib/intent/search-constraints.ts | 通用比较语法、原话数值校验、条件去重，不维护商品功能枚举 |
| lib/catalog/measurement.ts | 有限物理单位与量纲换算，非商品问法映射 |
| lib/catalog/spec-matching.ts | 基于真实规格的确定性比较、直接条件证据和通用澄清 |
| lib/catalog/condition-assessment.ts | 未能直接匹配的条件批量语义校验，只读并核实原文引用 |
| lib/catalog/products.ts | 参数化目录召回、规格过滤、游标续扫和候选结果 |
| lib/agent/auto-shopping.ts | 保留用户原始查询；未核实条件先返回 needs_clarification |

执行：解析 → 校验 → 目录别名/主体召回 → 数值约束比较 → 条件证据校验 → 返回候选与澄清，或进入既有购物流程。语义评估只接收商品描述与规格，不提供评论、用户私密数据、内部排序分或购买工具。

数值门槛必须有原话依据，不从“大容量”等偏好猜数值。属性无法精确匹配时，仅在量纲对应唯一规格键时允许按单位消解；多个规格键同量纲时不猜。单位不支持、规格缺失、无法比较时不作为已满足条件。

语义判断只接纳已请求的商品 ID 和条件 ID，证据必须连续存在于目录描述或单项规格；缺条目、重复冲突、假引用、模型超时和失败均为 unknown。明确矛盾的必需条件过滤，未知条件保留候选并澄清；偏好不作为硬过滤。语义模型仍有判断误差，不能取代目录质量和测试。

保持目录原有排序和游标含义，过滤后续扫补足页面，不开放客户端排序或 SQL 输入。不新增数据库迁移、依赖或支付/库存写入。本次不引入向量召回或新的偏好排序策略。

## 任务与兼容

needs_clarification 沿用已实现的终态：保留候选与原因，释放活动任务，禁用确认/推进，不产生购物车或订单写操作，用户重新提交完整需求。现有取消、报价、下单幂等与授权不改。

支付、订单、库存、授权与费用规则如需另行改变，状态为 `needs_human_review`。

## 验证

单元测试覆盖通用属性、条件、单位换算、原话数值、否定、缺数据、假证据、模型故障与历史合并；购物流程测试验证澄清无加购或订单副作用。真实目录检查仅执行只读模型/检索调用，不创建订单或预留库存。
