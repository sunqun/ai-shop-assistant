# 需求功能清单：购物助手双交互模式

状态：双模式核心流程已实施（2026-11-20）。范围：桌面网页商城的 `/assistant`；不包含移动端适配。下述未确认的扩展业务规则仍保留评审标记。

当前落地：自动报价展示 3 秒；沿用现有 AI 下单授权；取消后保留现有购物车/预留的自然过期规则；离页后不再推进新的下单请求，返回页面恢复的自动任务须点击“继续执行”。执行请求已进入创建订单时不受页面关闭影响，恢复后查询原结果。

页面展示补充：商品卡片展开品牌、分类、描述、规格、库存和评价信息，并提供完整详情入口；报价卡片不展示有效期，保留应付和费用明细。仅调整展示，服务端报价有效期校验继续生效。

## 目标与已明确需求

- 同一页面可演示两种交互模式：现有的用户确认下单模式，以及无需逐单确认的自动流程模式。
- 自动模式保留取消入口；取消成功后停止直接下单，转为生成支付短链。
- 开始创建订单后隐藏取消入口。
- 两种模式复用搜索、选品、加购、报价和现有交易服务，不复制两套业务逻辑。

## 推荐功能

| 编号 | 功能 | 建议行为 |
| --- | --- | --- |
| F01 | 模式切换 | 空闲时可选“确认后下单 / 自动下单”，默认保留现有确认模式；任务开始后模式冻结。 |
| F02 | 手动模式 | 搜索 → 选品 → 加购 → 报价 → 等待用户确认；确认后进入创建订单，取消则转短链。 |
| F03 | 自动模式 | 搜索 → 选品 → 加购 → 报价 → 可取消的短暂展示期 → 自动创建订单，不要求点击确认。 |
| F04 | 可见进度 | 页面显示真实服务端阶段，不用模型文案或前端模拟计时推断是否已下单。 |
| F05 | 取消边界 | 服务端原子决定取消与开始创建订单谁先成功；开始创建订单后拒绝取消，前端隐藏按钮。 |
| F06 | 提前取消 | 搜索/选品期间取消后不再启动加购、报价或下单；允许正在进行的只读搜索完成并确定商品后生成短链。没有可用商品时结束为“已取消，暂无可生成短链的商品”。 |
| F07 | 取消反馈 | 接受取消后立即进入“正在取消并生成短链”；短链未实际生成前不得显示生成成功。生成失败保持已取消状态，可单独重试短链。 |
| F08 | 防重复 | 创建任务、确认、取消、创建短链及下单均有稳定幂等标识；重复请求复用同一结果。 |
| F09 | 结果恢复 | 通过 taskId 查询最新进度；刷新或轮询失败不自动重复下单。订单结果未知时查询对账，不能直接提示未下单或转短链。 |
| F10 | 既有门禁 | 保留登录、现有 AI 下单授权、库存和报价校验；自动模式仅取消逐单确认操作。 |

## needs_human_review

- **授权与订单**：自动模式是否可沿用现有 `is_authorized` 的授权范围，还是需另有演示级开关或自动模式授权；选择模式不应自行解释为新增授权。两种模式均不默认代表支付或扣款授权。
- **交互时间**：自动模式建议报价后展示约 3 秒的取消窗口，时长待确认；由服务端给出 `commitAfter`。若选择无等待，报价阶段可能很快结束，取消机会更短。
- **库存**：取消后如何释放现有 AI 购物车预留、是否保留购物车，以及短链接续时的库存重验策略，需与既有交易逻辑核对。
- **价格与费用**：短链对应商品和数量，但取消时的报价不自动承诺延续到短链结算；币种、运费、优惠和报价变化展示规则待确认。
- **页面离开**：自动任务在断网、关闭页面或刷新后是否继续；建议演示版在创建订单前失去心跳时暂停，创建订单后继续查询最终结果。具体心跳期限与恢复行为待确认。
- **任务隐私与保留**：任务查询仅限当前用户；存储字段、保留时长和清理机制待确认。

## 验收重点

1. 同样商品请求可分别演示确认模式和自动模式，任务运行中不能改模式。
2. 自动模式正常运行时无需用户点击确认；报价、订单均来自真实工具结果。
3. 取消成功的任务绝不开始创建订单；开始创建订单的任务绝不显示取消成功或生成取消短链。
4. 取消与自动提交同时到达时，服务端只认定一个获胜分支。
5. 提前取消、重复取消、短链失败、报价过期、库存变化、刷新和订单响应丢失均有明确状态。
